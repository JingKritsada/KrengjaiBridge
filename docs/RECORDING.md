# อัดคลิป demo

มี 2 ส่วน:
- **ส่วนเว็บ**: อัดอัตโนมัติด้วยสคริปต์ มีคำบรรยาย EN/TH รันซ้ำได้ทุกครั้งที่แก้ UI
- **ส่วน LINE บนมือถือ**: อัดหน้าจอแยก แล้วตัดต่อรวม (ดูหัวข้อ 4)

## 1. เตรียมเครื่อง (ครั้งแรกครั้งเดียว)

| ต้องมี | ติดตั้ง | ใช้ทำอะไร |
|---|---|---|
| uv | `brew install uv` | รันสคริปต์ Python พร้อม dependency |
| Chromium ของ Playwright | `uv run --with playwright playwright install chromium` | เบราว์เซอร์ที่ใช้อัด |
| ffmpeg | `brew install ffmpeg` | แปลง WebM เป็น MP4 และตัดต่อ (ถ้าไม่มีจะได้ไฟล์ `.webm`) |

## 2. อัดส่วนเว็บ

```bash
cd kreng-jai-bridge
uv run scripts/record_demo.py                                   # 1536×864 → ./demo.mp4
uv run scripts/record_demo.py --base-url http://localhost:8000  # อัดจาก server ในเครื่อง
uv run scripts/record_demo.py --no-captions --headed            # วิดีโอไม่มีคำบรรยาย (ยังได้ .srt) และเปิดหน้าต่างให้ดูระหว่างอัด

# ซ้อมด้วยข้อมูลจำลอง ไม่ต้องมี server จริงหรือ LLM
python3 -m http.server 8099 --directory app/static &
uv run scripts/record_demo.py --mock --out /tmp/dry.mp4
```

- สคริปต์เปิดทุกหน้าใน **โหมดอัด** (`?rec=1`): ขั้นตอน pipeline โชว์ช้าลง (900 ms ต่อขั้น), กล่องข้อความรีเฟรชทุก 1 วินาที
  และมีวงแหวนสีเขียวรอบปุ่มก่อนคลิกทุกครั้ง เพราะวิดีโอของ Playwright ไม่มีเคอร์เซอร์
- โหมดอัดทำให้แอนิเมชันช้าลงเพื่อให้เห็นชัดในวิดีโอ 30 fps: ของที่เข้ามาใหม่ 480 ms, ตัวเลขนับ 1200 ms (เช่น 3 → 0),
  ระยะห่างระหว่างรายการ 90 ms และปุ่มค้างสถานะ "กด" 240 ms (คลิกของ Playwright ยาวแค่ ~1 ms) ตัวเลขทั้งหมดอยู่ใน `DESIGN.md` หัวข้อ 7
- สคริปต์เปลี่ยนหน้าด้วย `location.assign()` ในหน้าเว็บ (ไม่ใช้ `goto`) เพื่อให้เห็นการเปลี่ยนหน้าแบบ view transition:
  หน้าเก่าจางออก 200 ms หน้าใหม่ขึ้นมา 400 ms และแถบใต้เมนูเลื่อนไปยังหน้าใหม่
- ได้ 3 ไฟล์ข้างกัน เช่น `demo.mp4`, `demo.srt` (คำบรรยาย EN/TH หนึ่งบรรทัดต่อภาษา จับเวลาจากการรันจริง) และ
  `demo.events.json` (เวลา ตัวเลือก และข้อความของทุกคลิก ใช้วางมาร์กเกอร์ในโปรแกรมตัดต่อ)
- คำบรรยายแบบฝังในวิดีโอใช้ซ้อมดูเท่านั้น ตัวจริงให้ใช้ `--no-captions` แล้วใส่ `.srt` ในโปรแกรมตัดต่อ
  (IBM Plex Sans Thai, EN 36 px / TH 32 px บน 1080p)
- วิดีโอที่ Playwright อัดเองได้ขนาดเท่าหน้าจอ 1536×864 เสมอ (ขยายเป็น 2560×1440 ไม่ได้) ใช้ซ้อมและตรวจจังหวะ
  ตัวจริงอัดด้วย OBS จับหน้าต่างของ `--headed` (Retina 2× ได้ 3072×1728, 30 fps คงที่) หรืออัดจากหน้าจอจริงด้วย `scripts/record_live.py` (หัวข้อ 2.1)
- เก็บไฟล์วิดีโอไว้นอก repo ที่ `../LiveDemo_Videos/` (โฟลเดอร์ข้าง repo) ตั้งชื่อตามวันที่ เช่น
  `uv run scripts/record_demo.py --out ../LiveDemo_Videos/2026-10-20_web_walkthrough.mp4`
  ไฟล์ `.mp4`/`.webm` ถูก ignore ใน git เพราะขนาดใหญ่
- ใช้เวลาประมาณ 2.5–3 นาทีเมื่อใช้ endpoint ของคอร์ส และประมาณ 4–5 นาทีเมื่อสลับไปเครื่อง GPU ของทีม (โมเดล 9B ช้ากว่า)
- **สคริปต์จะกด "ล้างข้อมูลเดโม" บน server ที่ระบุ** อย่ารันระหว่างที่คนอื่นกำลัง demo อยู่บน server เดียวกัน
- ถ้าหน้า `/demo` ขึ้นป้าย "โหมดสำรอง (ไม่มี LLM)" ในคลิปก็จะเห็นป้ายนั้นด้วย ตรวจ `https://<server>/api/health` ก่อนอัด ช่อง `llm_available` ต้องเป็น `true`

ลำดับฉากในคลิป (คำบรรยายอยู่ใน `CAPTIONS` ของ `scripts/record_demo.py`):

| # | หน้า | สิ่งที่เกิด | คีย์คำบรรยาย |
|---|---|---|---|
| 1 | `/` | หน้าแนะนำ | `intro` |
| 2 | `/demo` | ล้างข้อมูล → PR รอรีวิวนาน → มิ้นกด "ช่วยเตือนให้หน่อย" → แท็บพี่สมชายเห็นข้อความเตือนที่ไม่มีชื่อมิ้น | `pr`, `ask`, `nudge` |
| 3 | `/demo` | มิ้นพิมพ์ความเห็น → ทดสอบการปกป้องตัวตน 6 ขั้น → คำที่ถูกขีดฆ่า → รอบทดสอบเดาตัวตน | `share`, `pipeline`, `markers`, `attacker` |
| 4 | `/demo` | ยืนยันส่ง → ประตูนิรนาม 1/3 → เพื่อนร่วมทีม 2 คน → 3/3 | `confirm`, `gate`, `teammates` |
| 5 | `/manager` | รอธีมขึ้น (สูงสุด 2 นาที) → พิมพ์คำตอบ → ยอมรับข้อเสนอ → ส่ง | `manager`, `reply` |
| 6 | `/demo` | มิ้นได้รับคำตอบ → ข้ามเวลา 2 สัปดาห์ | `heard` |
| 7 | `/manager` | ติดตามผล 3 → 0 ที่หัวการ์ด | `followup` |
| 8 | architecture | ภาพสถาปัตยกรรมบน Huawei Cloud และ LINE OA | `outro`, `line` |

## 2.1 อัดจากหน้าจอจริง พร้อม LINE บน iPhone (`scripts/record_live.py`)

สคริปต์นี้ใช้ได้เฉพาะ macOS มันเลื่อนเคอร์เซอร์จริง (เห็นในวิดีโอ) อ่านข้อความบน iPhone Mirroring ด้วย OCR ภาษาไทยของ Apple Vision
และอัดทั้งจอด้วย ffmpeg ได้ภาพ 4K 16:9 (3840×2160) จากเฟรม 1920×1080 pt ที่ y = 100

```bash
uv run scripts/record_live.py web  --out ../LiveDemo_Videos/2026-10-20_take-web    # เว็บอย่างเดียว เต็มเฟรม
uv run scripts/record_live.py line --out ../LiveDemo_Videos/2026-10-20_take-line   # เว็บซ้าย + LINE จริงบน iPhone ขวา
uv run scripts/record_live.py line --dry                                           # ซ้อมโดยไม่อัดจอ
```

ก่อนอัด take `line`:
- เปิด iPhone Mirroring ปลดล็อก และตั้ง Settings → **Authenticate Automatically** (ไม่งั้นจะล็อกกลางคลิป)
- View → Actual Size แล้ว Zoom In 4 ครั้ง (หน้าต่าง 479×1049 pt) สคริปต์ย้ายหน้าต่างไปทางขวาเอง
- ใน LINE เปิดแชต Kreng-jai Bridge ที่ผูกเป็น "มิ้น" แล้ว และ **ลบประวัติแชต** (☰ → Settings → Delete chat history)
  สคริปต์ตรวจว่ามีข้อความใหม่โดยนับข้อความบนจอ
- ห้ามแตะเมาส์ระหว่างอัด สคริปต์เลื่อนแชตเล็กน้อยทุก 50 วินาทีเพื่อไม่ให้ iPhone Mirroring หยุดเชื่อมต่อ

ได้ไฟล์ `<out>.mp4` (ครอป 16:9), `<out>.raw.mp4` (ทั้งจอ), `<out>.srt` (คำบรรยาย EN/TH ตามเวลาวิดีโอ) และ `<out>.events.json`
หน้า `/demo` แสดงประตูนิรนามของความเห็นที่ยืนยันใน LINE ด้วย (`GET /api/demo/gate`) จึงกดปุ่มเพื่อนร่วมทีมต่อจาก LINE ได้

## 3. แก้คลิปเมื่อ UI หรือเนื้อเรื่องเปลี่ยน

ทุกอย่างอยู่ใน `scripts/record_demo.py`:
- **คำบรรยาย**: dict `CAPTIONS` (คู่ข้อความ อังกฤษ/ไทย ต่อฉาก) อังกฤษไม่เกิน 42 ตัวอักษร ไทยไม่เกิน 35 ตัว (ไม่นับวรรณยุกต์และสระบนล่าง)
  แต่ละคำบรรยายค้างอย่างน้อย (จำนวนตัวอักษร EN + TH) ÷ 17 + 1 วินาที สคริปต์รอให้เองก่อนเปลี่ยนคำบรรยายถัดไป
- **ข้อความที่พิมพ์**: ค่าคงที่ `FEEDBACK` (ความเห็นของมิ้น) และ `REPLY` (คำตอบหัวหน้า)
- **ลำดับฉากและเวลารอ**: เมธอด `Demo.run()` ปรับเวลาต่อฉากที่ `await self.wait(วินาที)`
- **ถ้าแก้ UI แล้วสคริปต์หาปุ่มไม่เจอ** (error `Timeout ... waiting for locator`) ให้แก้ตัวเลือกปุ่มใน `Demo.run()` ตัวเลือกที่ใช้มี
  (รายการเต็มอยู่ใน `DESIGN.md` หัวข้อ 12):
  - ข้อความบนปุ่ม: "ล้างข้อมูลเดโมและเริ่มใหม่", "ทดสอบการปกป้องตัวตน", "ยืนยันส่งความเห็น", "เพื่อนร่วมทีมส่งความเห็นคล้ายกัน", "ข้ามเวลา 2 สัปดาห์", "ช่วยเตือนให้หน่อย"
  - attribute: `button[data-scenario="pr_stale"]`
  - class: `.inbox-panel`, `.member-tabs`, `.live-pipeline`, `.gate-bar`, `.reply-form`, `.followup`
  - id: `#feedback-form`, `#removed-markers`, `#attacker-rounds`
- ใช้ `--headed` ดูว่าสคริปต์ค้างที่ฉากไหน

## 4. อัดส่วน LINE

> **iOS Simulator ใช้ไม่ได้:** Simulator ติดตั้งแอปจาก App Store ไม่ได้ เลยไม่มีแอป LINE ให้ใช้

ทางเลือกที่ใช้ได้ เรียงจากที่แนะนำ:

| วิธี | ได้อะไร | ข้อควรระวัง |
|---|---|---|
| **A. iPhone จริง + iPhone Mirroring / QuickTime** | ภาพตรงกับที่ผู้ใช้เห็นจริง มี quick reply ครบ | ต้องมี iPhone 2 เครื่องถ้าจะโชว์ทั้งมิ้นและพี่สมชาย |
| **B. LINE for Mac + LINE ส่วนขยาย Chrome** | 2 บัญชีบนจอเดียว อัดด้วย macOS ได้เลย และไม่กระทบ LINE บนมือถือ | เวอร์ชัน PC/Mac **ไม่แสดง quick reply** ให้พิมพ์แทน (ระบบรองรับแล้ว ดูตารางล่าง) |
| C. Android Emulator + LINE จาก Play Store | อัดได้ทั้งเครื่อง | **การ login LINE บัญชีหลักใน emulator จะย้ายบัญชีออกจากมือถือจริง** (LINE ใช้บนสมาร์ทโฟนได้ทีละเครื่อง) ใช้เฉพาะบัญชีสำรองที่มีเบอร์แยก |

**วิธี A**
- iPhone Mirroring (macOS 15+ และ iOS 18+): เปิดแอป iPhone Mirroring บน Mac แล้วอัดหน้าจอด้วย `Cmd+Shift+5` → Record Selected Portion
- QuickTime (ใช้สาย USB): QuickTime Player → File → New Movie Recording → กดลูกศรข้างปุ่มอัด แล้วเลือก iPhone เป็นกล้อง
- เครื่องที่สอง: ใช้ Screen Recording ใน Control Center ของ iPhone แล้ว AirDrop ไฟล์มาที่ Mac

**วิธี B**
- LINE for Mac (App Store) login บัญชีที่ 1 → ผูกเป็น "มิ้น"
- Chrome → ติดตั้งส่วนขยาย LINE แล้ว login บัญชีที่ 2 → ผูกเป็น "พี่สมชาย"
- การ login บน PC/Mac เป็นอุปกรณ์รอง ไม่ทำให้ LINE บนมือถือหลุด

**คำสั่งพิมพ์แทนปุ่ม (ใช้ได้ทุกเครื่อง)**

| ตอนไหน | พิมพ์ | ผล |
|---|---|---|
| ยังไม่ได้ผูกตัวละคร | `มิ้น`, `สมชาย`, `วรรณ`, `โบ๊ท`, `ฝน`, `ต้น` | ผูกเป็นคนนั้น |
| ได้ข้อความเตือน | `ช่วยเตือนให้หน่อย` / `ยังไม่ต้อง` / `ไม่มีประโยชน์` / `ปิดแจ้งเตือนแบบนี้` | เหมือนกดปุ่ม (ใช้กับข้อความล่าสุดที่ยังไม่ตอบ) |
| หลังได้การ์ดตัวอย่างความเห็น | `ยืนยัน` / `ยกเลิก` | ยืนยันหรือยกเลิกฉบับร่างล่าสุด |
| ทุกเมื่อ | `ช่วยเหลือ` | วิธีใช้ |
| ข้อความยาวอย่างน้อย 15 ตัวอักษร | ความเห็นใด ๆ | ส่งเข้า privacy pipeline แล้วได้การ์ดตัวอย่าง |
| ข้อความสั้นที่ไม่ใช่คำสั่ง | เช่น `งานเยอะ` | บอทขอรายละเอียดเพิ่ม (ไม่เปลือง LLM) |

## 5. ตัดต่อรวม (ffmpeg)

**วางจอเว็บกับจอมือถือคู่กัน** (ปรับมือถือให้สูงเท่าคลิปเว็บ):
```bash
ffmpeg -i demo.mp4 -i phone.mov -filter_complex "[1:v]scale=-2:900[p];[0:v][p]hstack=inputs=2" \
  -c:v libx264 -crf 20 -pix_fmt yuv420p side-by-side.mp4
```

**ตัดช่วง** (เช่น เอาวินาทีที่ 5 ถึง 1:30):
```bash
ffmpeg -ss 00:00:05 -to 00:01:30 -i demo.mp4 -c:v libx264 -crf 20 part1.mp4
```

**ต่อหลายคลิป** (ต้องเป็นขนาดเดียวกัน):
```bash
printf "file 'part1.mp4'\nfile 'phone-part.mp4'\nfile 'part2.mp4'\n" > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c:v libx264 -crf 20 -pix_fmt yuv420p final.mp4
```

**ใส่เสียงบรรยาย** (อัดเสียงด้วย QuickTime → New Audio Recording):
```bash
ffmpeg -i final.mp4 -i voice.m4a -map 0:v -map 1:a -c:v copy -c:a aac -shortest final-voice.mp4
```
