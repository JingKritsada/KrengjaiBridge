# ต่อ LINE OA เข้ากับ Kreng-jai Bridge (ละเอียด)

ค่าที่ใช้:

| รายการ | ค่า |
|---|---|
| LINE OA | Kreng-jai Bridge (`@075bvvrs`) |
| Webhook URL | `https://119-13-81-32.sslip.io/line/webhook` |
| Health check | `https://119-13-81-32.sslip.io/api/health` (ต้องเห็น `"line_enabled":true`) |

สถานะตอนนี้:
- Server รับ webhook ได้แล้ว
- ตั้ง URL ผ่าน API แล้ว และ test ได้ 200 OK
- เหลือแค่เปิดสวิตช์ **Use webhook** (ตอนนี้ API ยังตอบ `"active": false`)

---

## ส่วน A — LINE Official Account Manager (ตั้งโหมดตอบกลับ)

1. เปิด https://manager.line.biz แล้ว login ด้วยบัญชี LINE ที่สร้าง OA
2. เลือกบัญชี **Kreng-jai Bridge**
3. กด **ตั้งค่า (Settings)** รูปเฟืองมุมขวาบน
4. เมนูซ้ายเลือก **Messaging API**
   - ต้องเห็น `Status: Enabled` (ใช้งานอยู่) และมี Channel ID
   - ถ้ายังไม่ได้เปิด ให้กด **Enable Messaging API** แล้วเลือก provider "Kreng-jai Bridge"
5. เมนูซ้ายเลือก **การตอบกลับ (Response settings)** แล้วตั้งให้ตรงตามนี้

   | ตัวเลือก | ค่า | เหตุผล |
   |---|---|---|
   | แชท (Chat) | **ปิด** | ถ้าเปิด บัญชีจะเข้าโหมดคนตอบเอง |
   | ข้อความทักทาย (Greeting message) | **ปิด** | บอทส่งข้อความต้อนรับและให้เลือกตัวละครเอง |
   | ข้อความตอบกลับอัตโนมัติ (Auto-response) | **ปิด** | ถ้าเปิดจะมีข้อความซ้อนกับบอท |
   | Webhook | **เปิด** | |

   UI บางเวอร์ชันมีตัวเลือก "Response mode: Bot / Chat" ให้เลือก **Bot**

## ส่วน B — LINE Developers Console (เปิด webhook)

1. เปิด https://developers.line.biz/console/
2. เลือก Provider **Kreng-jai Bridge** แล้วคลิก channel **Kreng-jai Bridge** (ชนิด Messaging API)
3. ไปที่แท็บ **Messaging API** แล้วเลื่อนลงไปหาหัวข้อ **Webhook settings**
4. **Webhook URL**
   - ต้องเป็น `https://119-13-81-32.sslip.io/line/webhook`
   - ถ้าว่างหรือไม่ตรง: กด **Edit** → วาง URL → **Update**
5. กด **Verify** → ต้องขึ้น **Success**
   - ถ้าขึ้น error ให้ข้ามไปส่วน D
6. **Use webhook** → เปิดสวิตช์ให้เป็นสีเขียว **(ข้อนี้คือขั้นที่ยังขาดอยู่)**
7. **Webhook redelivery** → ปิดไว้ (ระบบกันข้อความซ้ำอยู่แล้ว แต่ปิดไว้จะได้ไม่มี event ซ้ำตอน demo)
8. **Error statistics aggregation** → เปิด (ไม่บังคับ) จะช่วยดูสาเหตุถ้าส่งไม่ถึง
9. เลื่อนขึ้นไปหัวข้อ **LINE Official Account features** ตรวจว่า
   - Auto-reply messages = **Disabled**
   - Greeting messages = **Disabled**

   ถ้ายังไม่ใช่ กด Edit แล้วจะเด้งไปหน้าตั้งค่าในส่วน A

หลังทำข้อ 6 แล้ว ผมเช็กจากฝั่งเครื่องได้ด้วยคำสั่งนี้ (ต้องได้ `"active":true`):

```bash
cd kreng-jai-bridge && T=$(grep LINE_CHANNEL_ACCESS_TOKEN .env.line | cut -d= -f2-) && \
curl -s https://api.line.me/v2/bot/channel/webhook/endpoint -H "Authorization: Bearer $T"
```

## ส่วน C — ผูกมือถือกับตัวละครในเดโม และทดสอบ

> Quick reply (ปุ่มใต้ข้อความ) แสดงเฉพาะใน **LINE บนมือถือ** บน LINE PC/Mac ให้**พิมพ์แทนกดปุ่ม** ได้ เช่น
> พิมพ์ `มิ้น` เพื่อผูกตัวละคร, `ช่วยเตือนให้หน่อย` เพื่อตอบข้อความเตือน, `ยืนยัน` / `ยกเลิก` สำหรับฉบับร่าง, `ช่วยเหลือ` เพื่อดูวิธีใช้
> (ตารางคำสั่งเต็มอยู่ใน [../RECORDING.md](../RECORDING.md) หัวข้อ 4)

1. มือถือเครื่องที่ 1 สแกน QR ในแท็บ Messaging API หรือค้นหา `@075bvvrs` แล้วกด **เพิ่มเพื่อน**
2. บอทตอบ "คุณคือใครในทีมเดโม" พร้อมปุ่มรายชื่อ 6 คน ให้กด **มิ้น**
   - บอทตอบ "เชื่อมต่อแล้ว ..."
3. (ไม่บังคับ) มือถือเครื่องที่ 2 ทำข้อ 1–2 แต่กด **พี่สมชาย** เครื่องนี้จะได้ข้อความเตือน PR แบบเป็นกลาง
4. ทดสอบการเตือน PR
   - เปิด https://119-13-81-32.sslip.io/demo
   - กด **ล้างข้อมูลเดโมและเริ่มใหม่** (การผูก LINE จะยังอยู่) แล้วกด **PR รอรีวิวนาน**
   - มือถือมิ้นได้ข้อความ "PR #123 รอ review เกิน 48 ชั่วโมง ..." พร้อมปุ่ม
   - กด **ช่วยเตือนให้หน่อย** แล้วมือถือพี่สมชาย (หรือแท็บพี่สมชายในหน้าเว็บ) ได้ข้อความเตือนที่ไม่มีชื่อมิ้น
5. ทดสอบความเห็นนิรนาม
   - ในแชทมิ้น พิมพ์ `หนูไม่กล้าบอกพี่หัวหน้าค่ะ ว่าสั่งงานเย็นวันศุกร์ทำให้หนูต้องยกเลิกนัดตลอด`
   - รอ 3–8 วินาที บอทตอบเป็นการ์ดตัวอย่าง (สถานการณ์ / ผลกระทบ / สิ่งที่ขอ) พร้อมปุ่ม **ยืนยันส่ง** และ **ยกเลิก**
   - กด **ยืนยันส่ง** แล้วบอทตอบ "รอครบกลุ่ม..."
6. ในหน้า `/demo` กด **เพื่อนร่วมทีมส่งความเห็นคล้ายกัน** แล้วเปิด `/manager` รอ 30–50 วินาทีให้ธีมขึ้น
7. ตอบกลับในหน้า `/manager` แล้วมือถือมิ้นจะได้ข้อความ "คำตอบจากหัวหน้าทีม..."

**เปลี่ยนตัวละครของมือถือเครื่องเดิม:** บล็อกบอท แล้วปลดบล็อก บอทจะถามใหม่ หรือกด "ล้างข้อมูลเดโม" ไม่ช่วย เพราะระบบตั้งใจเก็บการผูกไว้

**คำสั่งในแชท**
- `ความเห็น` หรือ `ช่วยเหลือ` → บอทอธิบายวิธีใช้
- ข้อความบนปุ่ม (`ช่วยเตือนให้หน่อย`, `ยังไม่ต้อง`, `ไม่มีประโยชน์`, `ปิดแจ้งเตือนแบบนี้`) → เหมือนกดปุ่มของข้อความเตือนล่าสุด
- `ยืนยัน` / `ยกเลิก` → จัดการฉบับร่างความเห็นล่าสุด
- ข้อความยาวอย่างน้อย 15 ตัวอักษร → ถือเป็นความเห็นนิรนามที่จะผ่าน pipeline (ข้อความสั้นกว่านั้นบอทจะขอรายละเอียดเพิ่ม)

## ส่วน D — แก้ปัญหา

| อาการ | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| Verify ขึ้น error / timeout | server ล่มหรือ URL ผิด | เปิด `/api/health` ต้องได้ `ok:true` ถ้าไม่ได้ให้แจ้งผม |
| Verify ผ่าน แต่เพิ่มเพื่อนแล้วบอทเงียบ | Use webhook ยังปิด หรือ Chat mode ยังเปิด | ทำส่วน A ข้อ 5 และส่วน B ข้อ 6 |
| ได้ข้อความทักทายอัตโนมัติซ้อนกับบอท | Greeting / Auto-response ยังเปิด | ปิดตามส่วน A ข้อ 5 |
| ไม่เห็นปุ่มใต้ข้อความ | เปิดใน LINE PC/Mac | ใช้มือถือ หรือพิมพ์ข้อความบนปุ่มแทน |
| กดเลือกตัวละครแล้วไม่มีอะไรเกิด | ตัวละครนั้นถูกมือถืออีกเครื่องผูกไว้แล้ว | เลือกตัวละครอื่น หรือให้เครื่องนั้นบล็อกบอทก่อน |
| ส่งความเห็นแล้วได้ "ยังไม่ผ่านการตรวจความเป็นส่วนตัว" | attacker ยังเดาตัวผู้เขียนได้ หรือ LLM มีปัญหา | ลองพิมพ์ใหม่ให้ยาวขึ้น ถ้าเป็นทุกครั้งให้ดู `/api/health` ช่อง `llm_available` |
| ข้อความ push จากบอท (เช่นเตือน PR) ไม่มา | โควตา push ของแพ็กเกจฟรีหมด | ดูยอดใช้งานใน OA Manager แล้วใช้กล่องข้อความบนเว็บ `/demo` แทน (ข้อความ reply ไม่กินโควตา) |
| เปลี่ยน channel secret/token | ค่าใน server เป็นค่าเก่า | แก้ `.env.line` แล้วบอกผม จะ sync ไป `.env.server` และ redeploy ให้ |
